# Telegram-бот учебного помощника

Созданный бот проекта: https://t.me/academic_rudn_azoyan28_bot. Для ответа ему требуется запущенный локальный процесс.

Бот использует тот же `src.agent.Tools`, SQLite `data/education.sqlite` и `artifacts/model.joblib`, что и Streamlit. При одновременном запуске из одной папки ответы и завершённые прогнозы появляются в общей таблице `requests`. У запросов Telegram режим имеет префикс `telegram:`. Все данные вымышлены; шкала оценок 2–5.

## Создать бота в Telegram

1. Откройте официальный https://t.me/BotFather и отправьте `/newbot`.
2. Название: «Учебный помощник». Пример username: `academic_rudn_azoyan28_bot`; если занят, добавьте цифры. Имя пользователя должно оканчиваться на `bot`.
3. Сохраните выданный токен у себя. Он даёт управление ботом. Не присылайте его в чаты и не публикуйте в GitHub.

Официальная инструкция: https://core.telegram.org/bots/tutorial. Реальный токен в исходниках отсутствует.

## Запуск на подготовленном Mac

Дважды откройте `start_telegram.command` в папке проекта. В материалах задания есть также внешний файл «Запустить Telegram-бота.command». При первом запуске появится скрытый ввод: вставьте токен и нажмите Enter. Символы токена не отображаются. Скрипт проверит его через Telegram и сохранит в `data/telegram_config.json` с правами 600. Не закрывайте окно Терминала; остановка — Ctrl+C. Откройте созданного бота в Telegram и нажмите «Запустить».

Веб-приложение запускается отдельно. Два интерфейса используют общую базу, если запущены из одной и той же папки `academic-helper`. Копия проекта на другом компьютере будет иметь отдельную SQLite.

## Запуск после клонирования

Из корня репозитория перейдите в `academic-helper`, создайте `.venv` и установите `requirements.txt` по основной инструкции. Затем:

```bash
python -m src.etl
python -m src.telegram_bot --configure
python -m src.telegram_bot
```

Если хотите запускать скачанный файл двойным щелчком, один раз выполните `chmod +x start_telegram.command`.

Для последующих запусков ETL не нужен: он пересоздаёт базу и очищает прежний журнал. Дополнительные библиотеки Telegram не нужны — используется официальный HTTP Bot API и стандартная библиотека Python.

Альтернатива скрытому вводу — переменная окружения `TELEGRAM_BOT_TOKEN`, заданная локально. Параметры конфигурации: `mode` — `offline` или `local`; `allowed_chat_ids` — список разрешённых личных чатов. По умолчанию пустой список разрешает любые личные чаты с ботом. Групповые сообщения не обрабатываются. Telegram ID и имена отправителей в общий журнал не записываются; тексты вопросов и ответов записываются.

Файлы `telegram_config.json`, `telegram_state.json` и временные копии исключены через `.gitignore`. Не добавляйте их вручную через загрузку файлов на сайте GitHub. Архив для передачи кода тоже исключает эти файлы. Для смены токена запустите `--configure` повторно; для другого бота сохранённая позиция очереди сбрасывается автоматически.

## Что умеет бот

- `/stats` или кнопка «Статистика»: средние оценки и доля двоек. `/stats ud`, `/stats bd`, `/stats pr` выбирают дисциплину.
- `/predict` или «Прогноз»: пошаговый ввод дисциплины, оценок 2–5, занятий и работ. Проверяет согласованность счётчиков. Итоговая оценка в форму не вводится.
- `/predict ud-0001`: прогноз для существующей записи. Номера `bd-0001` и `pr-0001` относятся к другим дисциплинам того же студента.
- `/risk bd`: пять записей повышенного риска. Демонстрационный список использует всю базу; качество оценивается отдельно на тесте.
- `/quality`: F1, полнота, precision и ROC AUC на синтетическом тесте.
- `/repo`: ссылка на GitHub и последнее изменение кода, полученное через публичный GitHub API. Автоматической загрузки или выполнения кода из репозитория нет.
- `/mode`: обычные ответы по данным или локальная Qwen3, если MLX и веса доступны. Настройка режима относится только к текущему чату и сохраняется до перезапуска процесса. Внешняя платная LLM в Telegram не включена.
- `/help`, `/cancel`: справка и отмена ввода. Можно задавать вопросы обычным текстом.

При LLM-ответе проверенные сведения добавляются отдельно: смысловые ошибки модели возможны. Локальная LLM работает на Mac с Apple Silicon; подготовка описана в README.

## Репозиторий и работа без сервера

GitHub хранит исходники, данные и инструкции. Для работы бот должен быть запущен на Mac с интернетом. После закрытия окна, выключения компьютера или сна ответы прекращаются. Для круглосуточной работы потребуется отдельный постоянно работающий компьютер или сервер. Развёртывание такого сервера в эту версию не входит.

Бот использует long polling `getUpdates`: публичный IP, проброс порта, домен и HTTPS-сертификат для Mac не нужны. Если у этого токена уже установлен webhook, запуск останавливается с сообщением, не удаляя подключение. Одновременно запускайте только один процесс этого бота. При потере связи подключение повторяется; позиция очереди сохраняется после обработки сообщения. При неоднозначном сетевом сбое возможна повторная доставка ответа; гарантия «ровно один раз» не заявляется.

Официальная документация протокола: https://core.telegram.org/bots/api.

## Проверка

```bash
python -m pytest -q
```

Проверки охватывают общую базу, пошаговый прогноз, границы оценок и счётчиков, раздельные чаты, отмену, Unicode и размер сообщений, сокрытие токена в ошибках, права локального файла, polling, позицию очереди, список разрешённых чатов и существующий webhook. Запросы к Telegram в автоматических тестах имитируются; проверка настоящего диалога требует созданного бота и локально введённого токена.
